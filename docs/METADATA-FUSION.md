# 元数据字段融合清单

日期：2026-09-09。覆盖原 ScrapedMovieInfo 的 25 个字段，以及本轮新增的 actorCredits、unverifiedActorNames，共 27 个字段及 NfoWriter 派生节点。

用途：把多源合并、择优取值、派生字段分开。首版代码已实现并通过离线回归；尚未安装或真机重刮，不代表全库字段已正确，不授权设备写回。实现范围与残余限制见下文。

## 范围与前提

- 自动优先链的影片资料来源：DMM2、DMM 网页、JavLibrary、JavBus。JavDB 只提供演员、别名、头像及明确身份排除证据，不扩大到分类、导演或影片图片。Official/Missav 单源入口本次不扩展。
- 所有字段先校验影片身份；版本相关字段还要区分数字配信、DVD、租赁。相同番号不自动证明相同发行版本。
- DMM2 和 DMM 网页属于同一官方来源家族，不能计作两份独立身份证据；合并后的列表也不能冒充新的独立来源。
- 来源缺字段、来源请求失败、解析未覆盖是三种状态。空值或一次失败不能证明某个分类、演员或别名应被删除。
- 一阶段已确认的演员身份、主名和别名继续保留。未确认的旧字段不自动继承；v1 只作为恢复快照，不作为全部元数据真值。确定保留不等于把整个旧 NFO 混入全新刮削实验。

## 一、需要多源合并

```text
┌──────────────┬──────────────────────────────┐
│ 字段组       │ 合并方式                     │
├──────────────┼──────────────────────────────┤
│ 类型         │ 有据补充，按已知同义关系去重 │
│ 标签         │ 分类后合并，不照抄类型       │
│ 演员名单     │ 核对出演身份后补齐、去重     │
│ 演员别名     │ 绑定已确认身份，不按相似猜测 │
│ 导演名单     │ 核实联合执导后补齐           │
│ 演员头像候选 │ 按同一身份汇总，再选一张     │
└──────────────┴──────────────────────────────┘
```

这些字段不能因为第一份列表非空就停止收集，也不能无条件把所有结果并在一起。下面列出具体边界。

### 类型

字段：`genres`。NFO：genre。

汇总同影片资料中的有效内容分类；统一已核实的简繁、同义及跨语言对应，保留有依据的独有分类。未知词保留来源原文用于复核，不猜译、不按子串误合并。样片、促销、付费方式等站点功能不属于影片类型；互斥或疑似版本差异不强行并集。

### 标签

字段：`tags`。NFO：tag。

与类型分开判定。有证据的高清、VR 等技术或版本属性可归入标签；网站促销、样片可用性不自动进入影片标签。不得把类型整份复制为标签，也不得从网站页面宣称推断用户实际文件的分辨率或编码。用户自建标签不由刮削来源覆盖。

2026-09-09 AWTN-003 实证订正：DMM2 的详情 `ppvContent.relatedTags(limit: 50)` 才是相关标签，搜索 `keywords` 不代表此字段。`ContentTagGroup.tags` 中的成员与顶层 `ContentTag` 展开合并；组合关系保存在原响应证据中，NFO 按独立标签输出。DMM DVD/租赁仍只读独立的 `関連タグ` 栏，没有该栏时不从类型补造。

`tags` 在来源解析出口只包含独立标签，JavLibrary/JavBus/JavDB 不再复制 `genres`，MissAV 不再以类型栏补空标签栏。类型与标签可以有同名项，融合与 NfoWriter 不再删除这些独立标签。技术项归入标签、已核实名称归一化、样片和促销过滤保持既定规则。

用户文档只对应 AWTN-003：5 个类型链接、16 个相关标签链接，展开后为13个不重复标签。当前 `limit:50` 的真实响应返回26项、22个不重复标签，覆盖文档全部标签，但不等于官网展示22项。按既定技术归类，官方5类输出为4个内容类型和“高清”标签，合计23个标签；多源融合可另补有来源的分类。没有修改其他影片的预期或批量写回旧NFO。

### 演员名单与别名

字段：`actors`、`actorAliases`。NFO：actor/name；当前写入形式为主名加括号内别名，没有独立 alias 节点。

演员名单收集全部获准结构化来源，核对出演身份后合并。别名按同一身份挂接，去掉主名重复项，不能把另一位演员塞进别名。用户定案及来源明确别名属于确认依据；名单顺序、相似姓名、单演员名单共识只是线索，不自动升级为确认。头像相同也须检查是否为通用占位图，不能无条件证明同人。

假名核验范围按已确认制作商 `maker=豊彦` 判断，不以 MSAJ 番号前缀作为范围。用户确认该 maker 的影片多数使用作品假名，因此官方演员栏首先视作需核验的作品署名；“多数”不等于每个姓名都是假名，仍逐项判断。其它番号只要确认同一 maker 也适用；maker 缺失或冲突不能凭番号补造厂商。其它厂商也可能有假名，但不能仅因这条经验自动全部降级。

这只调整演员/别名证据的使用方式，不降级或丢弃豊彦官方的简介、时长、日期、厂商等独立字段。原已确认身份和署名文件不动。代码已移除 MSAJ 前缀分支，使用选定 maker 核验；低优先级来源的冲突 maker 或 JavDB 的 maker 不参与触发。

结构化演员全空时才按已有规则查评论候选并核验；评论正文不直接写入演员节点。已知假名不等于字段为空，不能借此直接启用评论自动写入。

假名处理需区分三种情况，不能把“非本名”一律当错误：

- 公开艺名、曾用艺名：有明确同人证据时归入演员身份及艺名别名，不追查私人本名。尚未认识的新艺名也不因陌生就判为剧情假名。
- 已确认的作品假名或角色署名：映射到已确认演员主名，保留本片署名及证据。只在对应影片范围使用，不自动升为所有影片通用别名，不单独凭假名搜索并绑定头像。已有 MSAJ 的 11 份确认别名及 MSAJ-018 原值不改写、不重审。
- 疑似假名且身份未确认：保留原始署名和来源作为待核候选，不擅自并入已知演员，不添加未经确认的身份别名，不猜配头像。已有确认演员不因该候选被替换；同一假名也可能属于不同人。若所有来源都只提供这类署名，只能报告身份待核，不能声称演员字段已经定案。

DMM 与外部站点重复同一作品署名，不自动证明它是通用艺名。新增 `actorCredits` 保存有明确同人依据的本片署名，写入标准 actor/role 节点；`unverifiedActorNames` 保存未核身份的署名并记录日志，不写成演员。只有待核署名而无可用演员时，NfoWriter 明确报错，阻止伪定案输出。新增字段不涉及数据库迁移；本片署名及未核姓名被排除在别名归一化、旧库演员补入和头像查询之外，也不会触发评论兜底。

制作商风险不否定已有身份依据。JavDB 演员主页成功解析且主名精确对应影片来源姓名时，记录为外部演员主页证据；但若外部来源还提供不同姓名，同名主页不能单独消除身份冲突。只有明确同人映射，或某一来源明确将相关姓名列为共同出演，才能解释不同名单；共同出演允许其它来源只列部分演员，并按明确别名匹配。空演员来源、分类词及已排除姓名/别名不参与冲突判定。冲突未解时，官方署名保持待核，同时从演员、头像候选和已核姓名中移除；外部可用演员保留，不自动猜同人或补造 role。主页无法访问、主名不符或只有其它影片页重复同一署名时，同样不能据此解除待核。来源明确给出另一个演员主名与本片署名的对应关系时，只把署名写入 actor/role。

未批量转换旧 NFO 中的括号别名，也未清除历史头像别名缓存。应用不维护人工确认 JSON，也不内置单片确认记录；全新刮削只采用当次来源证据，不能承诺恢复历史人工定案。原定案文件保持不变，后续对照仍需区分来源新证据与人工确认。不把整份旧 NFO 自动当作新源输入；身份待核时整片停止的行为未放宽。

### 导演名单

字段：`directors`。NFO：director，可重复节点。

这是名单，不应永远只取第一份非空列表。若可靠来源确认联合执导，则合并并去重；若来源各报一个不同导演，不能据此虚构联合执导，应保留冲突待审。导演关系不套用演员别名推断规则。

### 演员头像候选

字段：`actorImageCandidates`、`actorImageUrls`。NFO：actor/thumb。

先按已确认演员身份合并候选 URL，去掉无效、占位及重复候选。用户确认 DMM/FANZA 头像优先；没有可用 DMM 头像时，才从其它已确认同人且有有效图片的来源选择，沿用其它来源之间现有次序。本片假名不是头像身份证明，不因图片来自 DMM 就越过同人校验。

“可用”不只是 URL 非空：图片必须能读取、能解码、不是占位且属于同一演员。DMM 地址为空或图片无效时继续候选；全部候选失败则保持缺失/待补，不用空值覆盖已有正确头像。前者保存候选集合，后者保存所选结果；不是将多个头像同时写入一个 thumb。gfriends 属于现有头像补齐来源，不参与影片事实或演员身份定案。

## 二、择优取值或补空，不拼接

下面每组都要保留原值和出处用于冲突复核。当前代码已改成官方值保留、外部补空，并记录每次合并的候选字段来源与差异；这是中间候选日志，不是完整的最终逐字段审计。最终标题替换、评分保留和演员复核还会调整结果，不能只读最后一条候选日志作为最终出处证明。

来源边界：优先采用该商品的完整官方值，官方缺失时允许 JL/JB 补空。DMM2 与 DMM 网页按商品类型选用，不把两者当两份独立确认。简介补空优先 JB、其次 JL；其它外部来源沿用已有相对次序。已阻止明确数字/DVD/租赁跨类型字段互补，但当前来源没有统一发行版号；未知类型、同类型不同版本和互斥分类仍需证据复核，不把这层过滤称为完整版本确认。

1. 标题与正文：`title`、`originalTitle`、`plot`、`outline`。标题保留正确完整原文；展示番号由写入层处理。简介先用生产清洗函数消除 HTML 差异，再选择完整可信文本，不拼接各站简介，不以长度最大作为唯一依据。outline 选择可信摘要；缺失时可按现有写入规则复用 plot。标题/原题、正文/摘要需要一致，不能各取一站后形成自相矛盾内容。
2. 日期与时长：`premiered`、`year`、`runtime`。先确认所选发行版本和日期含义，不把租赁开始日当首次发行日，也不把 DVD/配信日期任取最早值。year 与选定日期一致；只有年份时允许保留有来源年份，不补造月日。时长择取有依据值，不平均，不冒充实测文件时长。
3. 制作信息：`studio`、`publisher`、`series`。分别选择制作商、发行厂牌和系列，外部来源可补缺。不能把 maker 和 label 合并成同一字段；不同机构名不擅自认作别名。series 当前是单值，跨站不同分类体系不直接拼接。
4. 评分与预告：`rating`、`trailer`。评分采用一个可说明来源及量表的有效值，不跨站平均；量表不明确时不擅自换算。预告按同商品和 2D/VR 属性选实际可用地址，不拼接、不猜造地址。
5. 影片图片：`thumbUrl`、`posterUrl`。按同商品、图片用途、质量和可用性选择；封面与竖海报不混为一谈，JavDB 影片图片仍排除。当前模型每种只存一个 URL，不能把多张候选拼成字符串。fanart 当前由 thumb 下载生成，不是独立刮削字段。

评分特别约束：rating 仍是一个字符串，NFO 没有单独携带来源量表。官方命中分支保持官方量表，不从外站不同量表补分；官方都未命中的分支仍使用 JL。统一输出量表和换算方式尚未实现，不平均、不取最高值；不能把数值非空当作评分融合已正确。

## 三、身份、排除与来源记录

- `number`：影片身份锚点，只规范化并校验；不同身份不得进入同一次融合。
- `excludedActorNames`：内部身份排除证据集合，不写入 NFO。只有明确来源依据才参与过滤；JavDB 演员链接的明确 male class 或演员主页独立的“男優”角色标记属于此类依据，角色词本身不是演员别名。缺少性别 class、主页失败、疑似姓名和一次空名单都不构成排除证据。与一阶段定案冲突时待审，不能静默删除已确认演员。
- `website`、`source`：分别标记选定主详情地址和主来源，必须对应同一结果。两者不能代表所有字段出处，也不是把全部来源名或 URL 串起来。字段级来源留在审计清单，实施时先复用现有日志/证据文件，不默认新增数据库子系统。

## 四、NFO 派生节点

```text
┌──────────────────┬──────────────────────────┐
│ 输入             │ 写入规则                 │
├──────────────────┼──────────────────────────┤
│ number           │ num、sorttitle           │
│ number + title   │ 展示标题加番号前缀       │
│ premiered        │ premiered、releasedate   │
│ studio           │ studio、maker            │
│ publisher        │ publisher、label         │
│ 演员身份与别名   │ actor/name               │
│ 所选演员头像     │ actor/thumb              │
└──────────────────┴──────────────────────────┘
```

这些是同一事实的写入映射，不算多份独立证据。year 需随已选日期校准；plot/outline 允许缺项互补但不盲目覆盖已有摘要。actor/type 当前固定为 Actor。封面文件、裁剪海报和 fanart 属于下载处理，不新增影片事实。

## 五、不参与刮削融合

收藏、已观看、播放进度、用户标签、媒体文件路径、STRM 地址、NFO URI、115 pickcode、登录会话和缓存键不从资料站合并或覆盖。用户状态保留与“隔离刮削结果能否重现事实”分别验证。若用户标签与刮削标签尚未区分来源，先明确存储边界，不按新规则全量清掉旧 tag。

## 实施与验证边界

```text
[来源结果] ──┬── 身份/版本核对 ── 排除错片与错版
             ├── 集合字段 ─────── 有据合并与去重
             ├── 单值字段 ─────── 择优、补空、列冲突
             └── 写入映射 ─────── 派生 NFO 节点
```

本轮已完成新版 video 结构化分流、同 CID 复用、停用来源边界、官方字段保留、分类合并/标签拆分、maker 假名核验及本片署名隔离。JavDB 演员主页成功解析的精确主名可解除对应待核项；失败时不降级成猜测。NfoWriter 已写 actor/role，NfoParser 现在读取 actor/name、actor/role、actor/thumb 到 NfoMetadata；尚未把 role 落入 Room 独立列，角色信息需在NFO读回层验证。真实 ANAV 搜索和客户端空壳完整响应已纳入夹具，不执行其中脚本。定向测试覆盖分类独有项、已核实词义去重、导演冲突、未知身份不合并、作用范围不扩散、头像候选顺序及不同发行类型不互补。

词表仅采用本次已有证据中的对应关系；未知词保留原文，不能声称支持全部跨语言分类。画像解码和旧头像延后替换已编译，但 Android 真机下载行为尚未验证。旧数据不因本轮代码自动迁移。

确认规则不等于确认全部影片值。不同发行版本和身份冲突仍按证据逐项复核，不拿旧 172 部矩阵作全库完成证明。ONET-012 建议值仍未批准写回。原库、一阶段 NFO 和 v1 保持不变；APK 已构建，未安装或重刮。
