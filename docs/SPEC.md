# HomeMovie 上下文续接规范

## 目标

在长对话压缩或切换新对话后，恢复当前任务，不重复已经完成的调查，也不把项目变成完整 Trellis 流程。

## 文件职责

- `docs/SPEC.md`：保存项目长期有效的决策、边界和工作规则，进 Git。
- `.codex/TASK-STATE.md`：保存当前活动任务，留在本机，不进 Git。
- 全局 `C:\Users\22451\.codex\AGENTS.md`：定义发现状态文件、恢复状态和更新状态的规则。

## 恢复顺序

1. 确认当前工作目录和分支。
2. 读取本文件和 `.codex/TASK-STATE.md` 顶部摘要。
3. 用 `git status --short --branch --untracked-files=no` 查看受跟踪文件状态。
4. 只核对状态文件列出的关键路径和证据。
5. 按“下一步”继续，不重新扫描整个仓库。

## 状态文件格式

顶部固定保留以下字段：

- 更新时间
- 项目、工作目录、Codex 任务
- 分支和 HEAD
- 当前状态
- 已确认
- 已修改
- 已验证
- 不要重复
- 下一步

状态只保留当前有效内容。旧结论被推翻时直接替换，不保留完整流水和命令输出。

## 创建和更新

- 短任务不创建状态文件。
- 任务跨两轮、改代码、跑测试或可能换对话时创建。
- 根因确认、代码修改、测试、提交和回复结束前更新。
- 中断或失败时保留状态、失败原因和下一步。
- 任务完成后清空状态；长期有效结论移入本文件。

## 工具和 skill 边界

- 不使用 hook。
- 不默认安装或接入完整 Trellis。
- `grill-me` 只用于需求讨论，不是项目状态层。
- 工程任务的第一条消息同时放真实 `i-have-adhd` 和 `lean-mode` skill 提及，下面可直接写任务正文。提及带有可读 `SKILL.md` 路径时，即使启动列表没有显示，也应读取该路径。
- `i-have-adhd` 在当前会话常驻；`lean-mode` 没有常驻声明，第一轮显式加载，后续只在准备增加校验、异常捕获、兜底、抽象、重试，或反复构建测试时重新读取。
- CodeGraph 暂不接入。只有复杂调用链仍反复调查时，才按项目单独启用。

## 并行任务

一个工作目录只对应一个活动任务。需要并行时使用独立 Worktree，各自维护状态文件。

## 模型策略

- 默认使用 `gpt-5.6-sol xhigh`。
- 连续两个工作周期仍是同一症状且没有新增证据、两次修复验证无效，或压缩后状态互相矛盾时，升级为 `gpt-6-astra high`。
- 单次测试失败、命令错误、网络故障、设备离线或外部来源异常不触发升级。
- 升级前先更新 `.codex/TASK-STATE.md`，再明确提示用户切换模型并发送“继续”。当前任务不能声称已自行切换模型。

## 复用

这套规则可复用于 `E:\JavDbEd2kMonitor`。每个项目分别维护自己的 `docs/SPEC.md` 和 `.codex/TASK-STATE.md`；不共享当前任务状态。

## 来源网络与代理边界

- HomeMovie 不接管云鸟、Clash Meta 或其它 VPN/TUN 软件，也不维护公共代理节点库。
- DMM/FANZA 需要实测可用的日本出口；JavDB 可能拒绝日本出口，也可能临时封禁个别非日本出口。用户在自己选择的单一代理软件中配置出口。
- 设置页提供的是 FlClash `0.8.96+` 示例，不是通用代理配置。其它软件、订阅和节点命名需按相同的域名分流原则自行调整。
- 本次 FlClash 示例只用脚本覆写，不点“一键填入”；已有自定义内容需自行合并。静态复制整份订阅策略组后，流量提示节点改名会导致 `proxy group ... not found`。
- 示例脚本按常见美国节点名称动态创建 `HomeMovie-JavDB` Selector，并置顶 `jdbstatic.com`、`javdb.com` 两条规则。使用独立组名，避免删除或覆盖订阅原有的 `jp`、`nonjp` 等常见策略组；节点命名不同时需修改筛选条件。该组由用户手动选择未被 JavDB 封禁的非日本节点，不能使用 URLTest。
- DMM/FANZA 不建立额外策略组或域名规则，沿用订阅原有链路，并在原策略组中手动选择实测可用的日本节点。
- FlClash 显示域名命中 JP 只能证明规则和出站链路生效。地区页还需用同一节点上的浏览器或等价请求作对照，不能仅凭落点归因于节点；电脑与设备结果不一致时先比较入口、请求头和实际出口。
- 应用内的来源测试只读取当前系统网络，区分可达、地区限制、当前出口被站点封禁、CF 验证和普通网络失败；测试不修改代理配置。
- “当前网络可访问”只表示探测请求通过网络层和已知拦截判断，不表示某个影片已通过详情身份校验或完整刮削。
- 某个来源不可用时，刮削链跳过该来源并继续其它来源。JavDB 保留为独立可选源。
- DMM 网页来源只查询“全部”搜索。它从结果页读取真实商品链接，同番号多入口时优先普通视频，其次旧数字视频和 DVD/租赁；不进入 `tv.dmm.co.jp` 的 TV Plus。搜索页失效时才按 CID 尝试 `video.dmm.co.jp/av/content`。
- 旧 DMM 搜索失败后的 CID 直查只认详情页 `og:url` 或 canonical 中的商品 ID；推荐区、脚本和请求地址回显中的番号或 CID 不能证明页面身份。

## 元数据融合和评论兜底边界

- 自动优先刮削先查 DMM2 和旧 DMM。任一官方来源命中后保留官方影片字段；演员、简介或演员头像证据不全时，再查询 JavLibrary、JavBus 和 JavDB。
- 官方标题标准化后只等于已确认的演员名或别名时，视为不完整标题；优先用 JavBus，其次用 JavLibrary 的完整标题替换。正常官方标题仍保持优先。
- JavDB 在自动优先链中只提供演员、别名和演员头像证据，不覆盖标题、简介、类型或影片图片。
- 多演员影片不能因官方来源只返回部分演员而停止。三个外部结构化来源都应完成查询，再按姓名、明确别名和同一头像证据归并演员身份。
- 评论只作最后的演员兜底。DMM/FANZA、JavLibrary、JavBus、JavDB 的结构化演员都为空时才读取；当前只支持 JavDB 短评，纯姓名换行清单或明确的“演员：”格式先产生候选，再用 JavDB 演员搜索逐名确认。普通评论不得写入演员字段。
