# HomeMovie 上下文续接规范

## 目标

在长对话压缩或切换新对话后，恢复当前任务，不重复已经完成的调查，也不把项目变成完整 Trellis 流程。

## HomeMovie NFO QC 总任务

1. 理清现有全部影片的正确 NFO 信息，逐项处理错误、缺失和冲突；证据不足的项目不能伪装成已确认。
2. 全部 NFO 定案后生成一份完整本地备份，保存设备路径、原始文件、最终文件和 SHA-256 恢复清单。
3. 备份校验通过后，清理应用内无用、多余或错误的缓存，以及影片/NFO 的索引缓存；不删除媒体源文件和最终 NFO 备份。
4. 从干净状态重新导入现有全部影片，让应用重新扫描和刮削。
5. 将新生成的 NFO、Room 记录、演员、图片和缓存与最终备份逐项对照；发现刮削漏洞后修复并重新验证。

清理前必须先只读确认缓存和持久数据的实际路径、用途及删除影响。真实设备上的删除、覆盖、清缓存和重新导入都需要用户当轮明确目标。

2026-09-09 用户确认后续采用新的 `Library3` / `STRM3` 隔离目录，从115每批导入5部不同番号的影片，逐字段核对来源、NFO及应用读入结果；同片分段/4K/附加播放源单列。先列精确清理范围并确认，再修已知读写缺口，随后开始导入。批内发现问题时暂停下一批，修复并复验后才继续。原Library、一阶段定案与v1备份保留；旧备份不作为所有字段无条件正确的证明。全库通过前不宣称刮削漏洞已全部排除。

## 文件职责

- `docs/SPEC.md`：保存项目长期有效的决策、边界和工作规则，进 Git。
- `.codex/TASK-STATE.md`：保存当前活动任务，留在本机，不进 Git。
- 全局 `C:\Users\22451\.codex\AGENTS.md`：定义发现状态文件、恢复状态和更新状态的规则。

## 恢复顺序

1. 确认当前工作目录和分支。
2. 读取本文件和 `.codex/TASK-STATE.md` 顶部摘要。
3. 用 `git status --short --branch --untracked-files=no` 查看受跟踪文件状态。
4. 只核对状态文件列出的关键路径和证据。
5. 按“下一步”继续，不重新扫描整个仓库。

## 状态文件格式

顶部固定保留以下字段：

- 更新时间
- 项目、工作目录、Codex 任务
- 分支和 HEAD
- 当前状态
- 已确认
- 已修改
- 已验证
- 不要重复
- 下一步

状态只保留当前有效内容。旧结论被推翻时直接替换，不保留完整流水和命令输出。

## 创建和更新

- 短任务不创建状态文件。
- 任务跨两轮、改代码、跑测试或可能换对话时创建。
- 根因确认、代码修改、测试、提交和回复结束前更新。
- 中断或失败时保留状态、失败原因和下一步。
- 任务完成后清空状态；长期有效结论移入本文件。

## 工具和 skill 边界

- 不使用 hook。
- 不默认安装或接入完整 Trellis。
- `grill-me` 只用于需求讨论，不是项目状态层。
- 工程任务的第一条消息同时放真实 `i-have-adhd` 和 `lean-mode` skill 提及，下面可直接写任务正文。提及带有可读 `SKILL.md` 路径时，即使启动列表没有显示，也应读取该路径。
- `i-have-adhd` 在当前会话常驻；`lean-mode` 没有常驻声明，第一轮显式加载，后续只在准备增加校验、异常捕获、兜底、抽象、重试，或反复构建测试时重新读取。
- CodeGraph 暂不接入。只有复杂调用链仍反复调查时，才按项目单独启用。

## 并行任务

一个工作目录只对应一个活动任务。需要并行时使用独立 Worktree，各自维护状态文件。

## 模型策略

- 默认使用 `gpt-5.6-sol xhigh`。
- 连续两个工作周期仍是同一症状且没有新增证据、两次修复验证无效，或压缩后状态互相矛盾时，升级为 `gpt-6-astra high`。
- 单次测试失败、命令错误、网络故障、设备离线或外部来源异常不触发升级。
- 升级前先更新 `.codex/TASK-STATE.md`，再明确提示用户切换模型并发送“继续”。当前任务不能声称已自行切换模型。

## 来源网络与代理边界

- HomeMovie 不接管云鸟、Clash Meta 或其它 VPN/TUN 软件，也不维护公共代理节点库。
- DMM/FANZA 需要实测可用的日本出口；JavDB 可能拒绝日本出口，也可能临时封禁个别非日本出口。用户在自己选择的单一代理软件中配置出口。
- 设置页提供的是 FlClash `0.8.96+` 示例，不是通用代理配置。其它软件、订阅和节点命名需按相同的域名分流原则自行调整。
- 本次 FlClash 示例只用脚本覆写，不点“一键填入”；已有自定义内容需自行合并。静态复制整份订阅策略组后，流量提示节点改名会导致 `proxy group ... not found`。
- 示例脚本按常见美国节点名称动态创建 `HomeMovie-JavDB` Selector，并置顶 `jdbstatic.com`、`javdb.com` 两条规则。使用独立组名，避免删除或覆盖订阅原有的 `jp`、`nonjp` 等常见策略组；节点命名不同时需修改筛选条件。该组由用户手动选择未被 JavDB 封禁的非日本节点，不能使用 URLTest。
- DMM/FANZA 不建立额外策略组或域名规则，沿用订阅原有链路，并在原策略组中手动选择实测可用的日本节点。
- FlClash 显示域名命中 JP 只能证明规则和出站链路生效。地区页还需用同一节点上的浏览器或等价请求作对照，不能仅凭落点归因于节点；电脑与设备结果不一致时先比较入口、请求头和实际出口。
- 应用内的来源测试只读取当前系统网络，区分可达、地区限制、当前出口被站点封禁、CF 验证和普通网络失败；测试不修改代理配置。
- “当前网络可访问”只表示探测请求通过网络层和已知拦截判断，不表示某个影片已通过详情身份校验或完整刮削。
- 某个来源不可用时，刮削链跳过该来源并继续其它来源。JavDB 保留为独立可选源。
- DMM 网页来源只查询“全部”搜索。它从结果页读取真实商品链接，同番号多入口时优先普通视频，其次旧数字视频和 DVD/租赁；不进入 `tv.dmm.co.jp` 的 TV Plus。搜索页失效时才按 CID 尝试 `video.dmm.co.jp/av/content`。
- 旧 DMM 搜索失败后的 CID 直查只认详情页 `og:url` 或 canonical 中的商品 ID；推荐区、脚本和请求地址回显中的番号或 CID 不能证明页面身份。

## 元数据融合和评论兜底边界

- 字段级规则单列在 [METADATA-FUSION.md](METADATA-FUSION.md)，覆盖类型、标签、演员/别名、导演、头像候选及单值选择和 NFO 派生映射。2026-09-09 已实现首版并通过离线回归，真机与全库字段复核未完成。原库、一阶段演员定案和 v1 不因规则调整自动写回。
- 自动优先刮削先查 DMM2 和旧 DMM；旧 DMM 命中也保留非空官方影片字段，JL/JB 按字段补空，不再整组覆盖。明确的数字/DVD/租赁跨类型资料不互补日期、时长、评分、预告和图片；来源未说明发行类型时不能宣称已完成版本核验。类型/标签汇总并仅按已核实映射去重；导演仅在有共同署名的联合执导名单间补齐。
- 官方标题标准化后只等于已确认的演员名或别名时，视为不完整标题；优先用 JavBus，其次用 JavLibrary 的完整标题替换。正常官方标题仍保持优先。
- JavDB 在自动优先链中只提供演员、别名和演员头像证据，不覆盖标题、简介、类型或影片图片。演员链接自身或紧邻节点的性别 class，以及演员主页明确的角色标记可作为性别证据；明确男演员进入排除集合，不把“男優”写成别名。没有性别标记的姓名继续保留，不能凭缺少 class 推断为男演员。
- 多演员影片不能因官方来源只返回部分演员而停止。三个外部结构化来源都应完成查询，再按姓名、明确别名和同一头像证据归并演员身份。
- 制作商 `maker=豊彦` 的影片存在作品假名，自动融合按选定 maker 保留核验边界，不按 MSAJ 前缀处理，也不凭标题提取别名。JavDB 演员主页成功返回并精确包含来源姓名时，还需排除不同来源的姓名冲突：外部不同姓名必须有明确同人映射，或有单一来源将两者列为共同出演，不能只凭同名主页断言是两个人；空演员来源、分类词及已排除姓名/别名不构成身份依据。外部来源明确给出的艺名与本片署名关系转为 actorCredits，以 NFO actor/role 保存，不进入全局别名或头像查询。其余署名保持待核，不因同名主页解除；只有待核署名而没有可用演员时 NFO 构建报错。应用不维护人工确认 JSON，也不内置单片确认记录。
- 演员合并保留精确姓名、显式别名及可用同一身份图片证据，移除“三源单演员共识”和相似姓名自动归并。头像优先 DMM/FANZA，再尝试其它有效同人候选；新图解码成功后才替换旧图，不在请求前清除旧头像。旧 NFO/头像缓存本轮未批量迁移。
- 评论只作最后的演员兜底。DMM/FANZA、JavLibrary、JavBus、JavDB 的结构化演员都为空时才读取；当前只支持 JavDB 短评，纯姓名换行清单或明确的“演员：”格式先产生候选，再用 JavDB 演员搜索逐名确认。普通评论不得写入演员字段。

## 隔离导入回归规则

- 设置页的批量多源重刮削只读取当前配置的影片库根目录，允许选择部分影片或全选，并复用单片重刮的 DMM/FANZA 优先多源链。它按影片顺序直接写回 NFO、图片和 Room，单片失败后继续并记录日志；不以收藏状态限定范围，也不创建元数据快照或额外缓存。
- 115 临时 STRM 缓存只能复用当前 DocumentsProvider、当前 STRM 根目录内的文件。按 document ID 的目录边界判断，不把 `STRM2` 当成 `STRM` 的子目录。
- 同一作品目录只保留一组作品级 NFO、poster、thumb 和 fanart，basename 截止到规范番号。`-U`、`-C`、`-WM`、分段和画质等播放源后缀只保留在 STRM 名称中，不构成不同作品；源文件名后段用 `^` 明确分隔的 1 至 3 位字母短标记也按播放源后缀保留，不从普通标题尾部猜测。扫描优先读取作品级元数据，再兼容旧播放源级文件；重刮不自动删除旧文件。
- 整目录导入暂不支持 FC2；生成 STRM 前识别 FC2 文件名，计入跳过并记录原因。
- 新 NFO 不输出空值、非数字、非有限数或非正数评分；保留有效评分原有精度。
- 旧 DMM 详情用 HTML 表格标签与值单元格配对，空系列不能读取相邻行或导航链接。竖版海报只采用页面实际提供的对应图片；无独立竖图时保留封面。
- DMM DVD/租赁详情字段同时兼容旧表格和当前 `dl/dt/dd` 结构；移动版简介读取 `area-productcomment` 或 `area-comment`，桌面版读取 `div.mg-b20.lh4 > p.mg-b20`。不能把图片帮助文案充当简介。
- 旧 DMM 网页请求使用 Android Chrome UA。桌面和移动模板均可能提供完整简介，只是 DOM 不同；用完整真实响应回放验证，不能只靠缩减夹具或合成标签。解析日志必须记录主要字段是否命中，不能只以标题或单个字段判定页面完整。
- 同番号 DVD 与租赁搜索结果并存时优先 DVD；CID 尾缀 `r` 仅在租赁路由内参与番号归一化。出租开始日期不写作原始发行日期；详情身份按 canonical/og:url 核对。
- 一个 DMM/FANZA 模板字段漏解析时，该来源的完整性复核必须扩展到全部映射字段和全部命中影片；不能只修空字段，也不能把旧 NFO 当作无条件真值。原备份保留为可恢复快照，全字段复核通过后另建新版本。
- 官方 HTML 与 NFO 的正文比较先用生产 `cleanMetadataText` 统一标签、实体及换行；保留原始值供追溯，不按 HTML 长度判定新增或丢失正文。来源值必须来自实际响应，不从融合 NFO 手填成“官方原值”；无法捕获解析中间值时明确标记缺证据。
- DMM2 或旧 DMM 缺发行日期、年份、时长等字段时，可用发行类型不冲突的 JL/JB 补空；年份跟随选定日期。JavDB 不参与这些影片字段。评分量表未统一，官方命中分支不从外部不同量表补分，官方全未命中的外部分支仍用 JL 评分，不做跨站平均或自动换算。
- DMM2 预告从同一详情请求读取 `sample2DMovie.highestMovieUrl`，为空时用 `hlsMovieUrl`，仅有 VR 样片时用 `sampleVRMovie.highestMovieUrl`。搜索命中和 CID 直查共用此规则；详情没有样片则保持空值，不推测地址。旧搜索的 `sampleMovie.mp4Url/hlsUrl` 与详情结构不同。
- 旧 DMM 搜索选中新版 video 入口时，按所选 CID 复用 DMM2 结构化详情，不解析客户端空壳；同 CID 已有结果时不再请求详情。CID 必须同时通过番号匹配与返回 ID 校验。用户停用 DMM2 时，旧 DMM 搜索仅选 DVD/租赁，不绕过停用设置查询数字接口。
- DMM2 类型只读 `ppvContent.genres`；相关标签只读同一详情的 `relatedTags(limit: 50)`，展开 `ContentTagGroup.tags` 和顶层 `ContentTag` 后去重。搜索页 `keywords` 不是详情相关标签，不回查或合并；网页数字分流和 CID 直查共用详情解析。
- 独立标签允许与类型同名，融合及 NFO 二次规范化不能按同名删除。JavLibrary/JavBus/JavDB 不再复制类型到标签，MissAV 只读独立标签栏；已核实词表、技术标签归类和样片/促销过滤保持原规则，不新增来源优先级或数据库迁移。
- `D:/Desktop/1.docx` 是用户提供的 AWTN-003 单片证据，不外推其他影片。真实响应与回归边界见 `app/src/test/resources/dmm2/awtn00003-detail.md`；离线回归不等于设备写回或全库字段已通过。
